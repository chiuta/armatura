# Changelog

All notable changes to ARMATURA are recorded here. The format follows [Keep a Changelog 1.1.0](https://keepachangelog.com/en/1.1.0/) and the project intends to follow [Semantic Versioning](https://semver.org/) once it has releases.

> **This changelog is reconstructed.** ARMATURA has had **no published release**: every crate is version `0.1.0`, there are no tags (the first builds are prepared as the draft pre-release `v0.1.0-alpha.3`, below) and no release notes were kept while it was built. The sections below were reconstructed in October 2026 from `ROADMAP.md` section 9 (the dated implementation log), `FEATURES.md`, the README feature levels and the review entries. The names "0.1" to "0.7" are **feature levels** that group what the sources say belonged together, not published versions; the order inside a level follows the order of the log; dates appear only where a source gives one (the log is headed 20 Oct 2026 but contains entries up to the licence decision of 22 Oct 2026). Where the log does not say when something happened, none is invented. When the first real release is cut, rename *Unreleased* and these levels to real versions (see [docs/DEVELOPMENT.md](docs/DEVELOPMENT.md), release checklist).

Related versions that **are** real and independent of the above: the Rust facade `API_VERSION` (1.0.0 to 1.4.0, below), the C and WebAssembly `ABI_VERSION` (1), and the project file `format` number ([docs/PROJECT_FORMAT.md](docs/PROJECT_FORMAT.md)).

### Draft pre-release `v0.1.0-alpha.3` (built 2026-10-24, not yet published)
Prepared from commit marker `[release v0.1.0-alpha.3]`; it supersedes the drafts `v0.1.0-alpha.1` and `v0.1.0-alpha.2` (never published). Same assets as alpha.2. Changes follow the first test on a real Windows 11 desktop (the double-click launcher, `armatura-studio` and the GIF / Lottie / HTML exports worked):
* **Fixed: UI settings were not kept on Windows.** The launcher printed "UI settings are kept for this session only (no config path)". The default path is now `%APPDATA%\ARMATURA\ui.json` (`$ARMATURA_UI_CONFIG` and `--ui-config` still win); unit test `config_path_lookup_per_platform`.
* **Fixed: the source offer said "not configured" in release binaries.** `release.yml` now sets `ARMATURA_SOURCE_URL` at compile time to the address of the building commit; `/source` and `--version` show it, `--source-url` overrides it, a plain `cargo build` still has none. The release smoke test checks it.
* **Fixed: exports in the window were silent.** `armatura-studio` now opens a native "Save as" dialog (`rfd`, MIT or Apache-2.0) starting in the project's folder and reports the saved path. Compiled and linted in CI; not yet tested by a person; on macOS the web view does not report the final path.
* **Documentation:** LIMITATIONS L-04, L-75, L-76 now state what was tested on Windows 11 (alpha.2) and what was not; STUDIO, CLI_REFERENCE, FAQ, GETTING_STARTED, SECURITY, DEVELOPMENT updated; the seven translations and the site follow.

### Documentation corrections found while writing (code left untouched)
The documentation follows the behaviour of the code. These places where comments or older text disagree with the code are recorded for the maintainers:
- `api.rs`: the doc comment of `ci_init` names the default manifest `ci.json`; the code uses `armatura-ci.json`.
- `armatura-capi/armatura.h`: says `armatura_render` returns the width and height "even on failure"; it does so only for the buffer-too-small result (-2). Says the last-error text is valid "until the next call"; it is overwritten only by the next *failing* call and never cleared by a success. `armatura_width` / `armatura_height` return rounded integers.
- `armatura-wasm/build-wasm.sh`: the closing hint for `js/test.mjs` omits the project path argument that the real-module branch requires (fixed in wave 7).
- `armatura-wasm/js/armatura.js`: `Armatura.instantiate(url)` does not check `response.ok`, which turns a 404 page into an "expected magic word" error (fixed in wave 7).
- `FEATURES.md` still lists as missing several features that exist (onion skin and trails, audio waveform, scripting, face tracking, glTF export); `README.md` (old) listed some commands under a level that the log places later.
- Version labels differ between README (v0.6), FEATURES.md (v0.5, ladder to v0.7) and the crates (0.1.0).

## Review waves and hardening (October 2026)

These were fix batches made after independent reviews of the same tree. Each fix has a regression test. They are listed by wave as the log orders them; none of them is a release.

### Wave 1 - adversarial security and robustness review
- **S1 studio.** `tiny_http` replaced by an own standard-library HTTP/1.1 server (`http.rs`): `Connection: close`, 10 s read deadlines, early 413 / 431, connection cap with 503. Host allow-list against DNS rebinding, `Content-Type: application/json` on POST, Origin / `Sec-Fetch-Site` proof on mutating routes, CSP, `nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy: no-referrer`; `/api/save` atomic and symlink-refusing.
- **S6 collab.** Token of at least 16 characters via header or `HttpOnly` cookie from a login POST (never in a URL), constant-time compare, failed-attempt rate limit, random 128-bit replica ids and a per-participant secret, log mode 0600, log hash FNV-1a replaced by SHA-256 (format v2).
- **S2 assets.** `assets::resolve`: every asset path is canonicalised and must stay inside the project directory (no absolute paths, `..`, symlink escapes) unless `--allow-external-assets`; regular files only; 256 MB audio and 64 MB image caps; ffmpeg and ffprobe get `-protocol_whitelist file` and `./`-prefixed names; an empty-parent bug that could let a URL reach ffmpeg was fixed.
- **S3 resource limits.** PNG header checks before allocation (more than 64 Mpixel or a side above 16384 refused), JPEG cap, raster output limits, `fuzz --samples` cap, near-linear GLB ear clipping (60000 anchors had taken 40 s), `check_budget` for exports, size-report and lod, a cap on `import-lottie` values.
- **S4 expressions.** Parser depth limit 64 and source limit 4 KB.
- **R1 finite values.** Project JSON floats beyond +-1e7 refused at load; `non-finite value in <place>` errors instead of writing NaN from render, frames, export, render-hdr and export-oca; container and scroll solvers reject non-finite results.
- **R2 atomic output.** `write_json` validates before writing; every CLI output is written atomically (`fsutil::write_atomic`, symlinks refused); commands refuse an output that is the input project; golden hashes and manifest paths validated; predictable `/tmp` names replaced by private 0700 exclusive temp directories.
- **R3** closed-pipe-safe `println!` / `eprintln!`. **R4** `check`, `lint` and `studio` report `unknown field <path>`; unknown keys in a machine transition or condition are an error. **R5** WASM documentation corrected: `catch_unwind` does nothing under `panic=abort`; `arm_render_rgba` refuses outputs above 256 MB.
- Removed: the `tiny_http` dependency (and `ascii`, `chunked_transfer`, `httpdate`).

### Wave 2 - licence and provenance review
- Ten findings of an independent review addressed. `unknownfields.rs` SPDX corrected; the SPDX audit test `armatura-cli/tests/spdx_audit.rs` added (also run by `scripts/licence-audit.sh`); easing functions `Bounce` and `Back` re-derived without third-party constants (values changed, new tests); hash-constant provenance cited; Schneider curve fitting worded as structure-follows-paper with the Graphics Gems terms noted; the AGPL section 13 offer implemented (`/source`, `--source-url`, footer link, `armatura --version`; tests in `source_offer.rs`); CONTRIBUTING now carries DCO 1.1 verbatim and no dual-licence right without a CLA; `REUSE.toml` added; the face model moved to `armatura-core/models/` so that packaging includes it; `docs/PATENT_NOTES.md` added.

### Wave 3 - correctness and functional review
- **C1 to C12 correctness.** Among others: iBUG68 eye and eye-aspect-ratio fixes, `frames --png`, the Lottie exporter with gradient alpha, dashes, caps and precomp groups plus a warnings report, SMPTE drop-frame timecode, loop seam `--inclusive`, error-diffused GIF delays, SVG mask alpha, nested stacks in OpenRaster import, chroma-aware `ci diff` SSIM, gradient stop sorting, blur at the canvas edge, FABRIK tolerance, gzip budget, the `ci init` fuzz gate, `--max-seconds`, lip-sync validation, OCA integers, `pick --tol` on fills and bones, `collab-sim ok`.
- **Functional review.** Depth of field goes through the engine compositor (blend modes, masks and layer effects survive; `dof --strength 0` equals `render` within 1/255); `dof-export` to .mp4 / .webm encodes real video or fails without a success message; `lod` keeps referenced layers and re-validates each level; Lottie import reads animated paths and the export-import round trip is tested; mapping files reject unknown keys; a run that produces nothing exits non-zero unless `--allow-empty`; legacy commands refuse unknown flags with a hint; `fuzz --only/--props`; `sound add` validates the file; glTF export lists dropped features; `physics merge=keep` with nothing baked is an error; mocap `--map Hips=bone`; `collab-sim` defaults to valid edits; tests no longer leak temp dirs; all compiler warnings removed.

### Wave 4 - regression review
- **H1** every command that writes a derived project validates against the input project's directory, and `write_json` rewrites relative asset paths or warns. **H2** `lod` leaves container and scroll members unreduced. **H3** per-command option tables (`ci run --prune` is a flag, `autotrace --png` takes a value, `export-oca --layers`, `keyedit --free`) and the USAGE-versus-parser test now covers every command.
- **M1** studio accepts `Origin: https://<allowed host>` and the new `--public-origin`; `--port 0` prints the real port. **M2** unknown keys in `ui.json` are ignored with a warning and the file is backed up before the first save. **M3** `--max-seconds` checked inside the candidate loops (a budget that expired part-way used to panic the linear scan). **M4** animated Lottie gradient handles imported as `grad_dx` / `grad_dy` channels. **M5** `write_atomic` falls back to an in-place overwrite when the directory is not writable (documented as not atomic); symlinks still refused.
- **LOW** items: the unknown-field probe ignores non-zero defaults; collab back-off per client address with the right token always accepted, duplicate `Host` gets 400, tokens with CR / LF / `;` refused; `ci` accepts global flags after the subcommand and `--key=value`; `<command> --help` and `--version`; several argument validations; `load_project` reads only regular files up to 256 MB (`--max-input-bytes`); Lottie import of a 20000-shape group is linear; `cargo clippy --workspace --all-targets` exits 0.

### Wave 6 - CLI contract review
- **Per-sub-command option validation.** Flags and value options are checked against the synopsis form that applies (`ci run|init|bless|diff`, `trail` both forms, `ui commands|layout|search`, `golden write|check`, `vcs <sub-command>`, `keyedit <edit>`, `pose-suggest`, `pose-db`, `clip`, `sound`, `container`, `scroll`, `bind`, `onion`): `ci diff ... --quiet`, `ci init ... --quiet`, `trail <bone> ... --json`, `ui layout presets --json`, `golden write --tol` are now refused, and the message names the sub-form that accepts the option. USAGE was restructured (one line per `vcs` sub-command, `golden write` and `golden check`) and completed (`render --proxy`, `export --codec/--columns`, `dof-export` `.mp4/.webm/--codec`, `idle --jitter`, `face-synth --fps`, `face-eval --scene/--json`, `face-detect --min-side/--max-side/--max-dim`, the `face-train` tuning options).
- **`golden`.** `write --scale` above 1 is refused instead of being clamped silently; `check --scale` is refused (the stored scale is used).
- **Docs.** `docs/CLI_REFERENCE.md` synopses equal USAGE (about 25 missing `keyedit` options and the options above added; `vcs` and `keyedit` synopses are now the USAGE lines); `docs/CI.md`: the `fuzz` check gates by default (tested), `gate: false` or `max_fail_rate >= 1` only informs; `docs/LIMITATIONS.md` L-73 updated.
- **Tests.** New: `options_are_validated_per_sub_command`, `usage_forms_split_alternatives`, `cli_reference_synopses_match_usage`, `cli_reference_repeats_usage_lines_verbatim`, `golden_scale_rules`, `fuzz_check_gates_by_default_and_gate_false_only_informs`, `json_quiet_allow_empty_acceptance_matrix`, `golden_scale_above_one_is_refused_and_check_has_no_scale`; `every_flag_the_code_reads_is_in_the_strict_tables` now checks every option read against the USAGE of the command that reads it.

### Wave 7 - the open items of the limitations list
- **A. Option validation.** `export` is validated per output extension (two pooled synopsis lines became one form per format family: a `.json` export refuses `--scale`, a `.glb` refuses `--scale`, `.mp4` is the only one with `--codec`, and so on); `keys shift|scale|...`, `idle`, `comp` and `snapshot` have one USAGE line and one option set per sub-command, with required options (`keys shift` needs `--by`, `keys scale` needs `--factor`) and a message naming the sub-form that accepts a refused option. Guard tests and `docs/CLI_REFERENCE.md` updated.
- **B. Behaviour.** L-71: a bone-attached layer inside a scaled or rotated group no longer doubles the posed bone motion (`skin * chain * local`; re-record goldens of such projects). L-70: `follow --chain` cuts at the project length instead of writing keys past it; soft IK works together with `stretch` above 1 (continuous and bounded); `make-loop` keeps removing travel by design and now reports that it did.
- **C. WebAssembly safety.** `armatura_core::clock` replaces every direct `Instant`, `SystemTime`, `process::id` and `thread::spawn` (host-fed clock through the new export `arm_set_clock`, fed by `armatura.js`); `tests/wasm_safety.rs` scans for new direct uses; `Armatura.instantiate(url)` checks `response.ok`; `build-wasm.sh` prints the full test hint. - **D.
