# Known limitations

*What OSATURA does not do, does only partly, or has not been shown to do. Collected from the "NOT done" and "limits that remain" statements of `ROADMAP.md` section 9, from the other documents and from what was seen while writing this documentation. Documentation CC-BY-4.0. Nothing here is hidden fine print: if a limit matters to you, open an issue.*

How to read the tables:

* **Severity** is the effect on a typical user: **High** = blocks a main use or can lose work or safety; **Medium** = a visible gap with a workable way round; **Low** = an edge case, a polish item or a research limit.
* **Workaround**: what you can do today. "None" means none known.
* **Roadmap**: the item in `ROADMAP.md` (R-xxx ordered plan, I-xx innovations) that the limit belongs to. A limit listed there as "NOT done" has no scheduled work; the roadmap id says where it was left.
* The ids `L-nn` are for referring to a limit from an issue or from another page.

Two facts shape everything below. First, **OSATURA has been built, tested and reviewed by one project in one environment** (Linux x86-64, no real GPU, no webcam, no browser other than headless Chromium, no network access to install further targets); what that environment could not do is listed as "not tested", not as "works". Since 24 Oct 2026 a second environment adds evidence: GitHub Actions runs the tests on Linux, macOS and Windows and builds the executables and the WebAssembly module (items L-01, L-04, L-59, L-61, L-64 say exactly what that proves). Second, **there is only a draft pre-release**: `v0.1.0-alpha.3` is built and prepared but not published, all crates are 0.1.0 and the version names "v0.5 / v0.6 / v0.7" are feature levels (see [CHANGELOG.md](../CHANGELOG.md)).

## 8. Runtime: state machines, layout, scripting

| Id | Limit | Severity | Workaround | Roadmap |
|---|---|---|---|---|
