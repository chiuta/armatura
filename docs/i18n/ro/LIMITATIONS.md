# Limitări cunoscute

*Ce nu face ARMATURA, ce face doar parțial sau ce nu s-a dovedit că face. Adunate din afirmațiile „NOT done” și „limits that remain” din `ROADMAP.md` secțiunea 9, din celelalte documente și din ceea ce s-a observat la scrierea acestei documentații. Documentație CC-BY-4.0. Nimic de aici nu este un text scris cu litere mici ascuns: dacă o limită contează pentru tine, deschide un issue.*

Cum se citesc tabelele:

* **Severity** (severitatea) este efectul asupra unui utilizator obișnuit: **High** = blochează o utilizare principală sau poate duce la pierderea muncii ori la probleme de siguranță; **Medium** = o lacună vizibilă, cu o cale de ocolire practicabilă; **Low** = un caz limită, un detaliu de finisare sau o limită de cercetare.
* **Workaround** (soluția ocolitoare): ce poți face astăzi. „None” înseamnă că nu se cunoaște niciuna.
* **Roadmap**: intrarea din `ROADMAP.md` (R-xxx plan ordonat, I-xx inovații) de care ține limita. O limită enumerată acolo ca „NOT done” nu are lucru planificat; id-ul din roadmap arată unde a fost lăsată.
* Id-urile `L-nn` servesc pentru a face trimitere la o limită dintr-un issue sau de pe altă pagină.

Două fapte stau la baza a tot ce urmează. În primul rând, **ARMATURA a fost construită, testată și revizuită de un singur proiect, într-un singur mediu** (Linux x86-64, fără GPU real, fără webcam, fără alt browser decât Chromium headless, fără acces la rețea pentru a instala alte ținte); ce nu a putut face acel mediu este enumerat ca „netestat”, nu ca „funcționează”. Începând cu 24 oct. 2026, un al doilea mediu adaugă dovezi: GitHub Actions rulează testele pe Linux, macOS și Windows și construiește executabilele și modulul WebAssembly (punctele L-01, L-04, L-59, L-61, L-64 spun exact ce dovedește asta). În al doilea rând, **există doar o pre-lansare ciornă**: `v0.1.0-alpha.3` este construită și pregătită, dar nepublicată, toate crate-urile sunt 0.1.0 și numele de versiune „v0.5 / v0.6 / v0.7” sunt niveluri de funcționalități (vezi [CHANGELOG.md](CHANGELOG.md)).
