# Provenance d'ARMATURA et procédure d'implémentation indépendante

ARMATURA est **implémenté de façon indépendante à partir de spécifications et d'articles publics ; les listes de fonctionnalités des concurrents ont été consultées pour délimiter le périmètre ; aucun code source tiers n'a été copié.** Ce n'est pas du « clean-room » au sens juridique strict (aucune équipe distincte n'a rédigé une spécification pour une seconde équipe), et ce fichier dit ce qui a été fait et ce qui ne l'a pas été. Ceci n'est pas un avis juridique ; c'est une discipline d'ingénierie qui garde la provenance vérifiable.

## Règles
1. **Entrées autorisées** : normes publiques (RFC, W3C, WCAG, PNG/APNG, OpenRaster, OCA, spécification Lottie), manuels et articles à comité de lecture antérieurs à la portée de leurs brevets, documentation publique et comportement *visible par l'utilisateur* des produits.
2. **Entrées interdites** : code décompilé ou désassemblé, sources ayant fuité, rétro-ingénierie de formats de fichiers propriétaires, SDK restreints par un CLUF, poids de modèles de fournisseurs, icônes, noms, chaînes d'interface ou contenus d'exemple d'autres produits.
3. **Provenance consignée par module** : la méthode et sa source publique (norme, article, manuel) sont nommées dans le commentaire de documentation du module et dans le journal ci-dessous. Une note de spécification écrite distincte par fonctionnalité (modèle à la fin) n'a **pas** été produite avant l'implémentation pour la plupart des modules ; cette procédure ne prétend pas le contraire. Lorsqu'un module suit de près un algorithme publié, le journal le dit.
4. **Noms et schéma propres** pour tout ce qui n'a pas de norme publique. Ne copiez pas la terminologie des produits.
5. **Examen des brevets** avant de livrer tout élément 🟡 ; préférez un autre algorithme à un contournement de conception. L'examen encore à faire est listé dans docs/PATENT_NOTES.md (ceci n'est pas un avis juridique).
6. **Dépendances** : licences permissives uniquement (MIT/Apache/BSD/Zlib/ISC/Unlicense/CC0) ; consignez chacune dans le tableau ci-dessous. Une exception : la feature `scripting` (une feature Cargo ACTIVÉE par défaut dans `armatura-core` et `armatura-cli` ; `--no-default-features` la désactive) fait venir `rhai`, qui fait venir `smartstring` (MPL-2.0+, copyleft au niveau du fichier). Elle est autorisée par son nom dans `deny.toml` ; un build avec `--no-default-features` ne contient aucune crate tierce MPL (vérifié paquet par paquet à la fin de docs/THIRD_PARTY.md).

## Divulgation de la recherche
La recherche de fonctionnalités à l'origine de FEATURES.md a été menée par un agent de recherche IA qui a examiné les dépôts publics, les journaux de modifications et la documentation d'autres outils **uniquement pour des idées de fonctionnalités et le périmètre** : rive-runtime, spine-runtimes, Pencil2D, Glaxnimate, Friction et des éditeurs compatibles Live2D, ainsi que les listes de fonctionnalités publiques de produits commerciaux. L'auteur ne peut pas attester que l'agent de recherche n'a lu aucun code source dans ces dépôts ; aucun code, tableau, constante, identifiant ou format de fichier issu d'eux n'a été utilisé intentionnellement, et l'implémentation a été écrite séparément à partir de spécifications publiques, d'articles et de mathématiques de manuel. Le code de ce dépôt a également été en grande partie écrit avec un modèle d'IA (voir LICENSING.md à propos de la paternité) ; ses données d'entraînement échappent au contrôle de l'auteur. Un relecteur qui a besoin d'une assurance plus forte doit considérer ceci comme une implémentation indépendante présentant un risque résiduel documenté, et non comme une garantie de clean-room.
