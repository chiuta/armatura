# Changelog

Todas as mudanças relevantes do ARMATURA são registradas aqui. O formato segue o [Keep a Changelog 1.1.0](https://keepachangelog.com/en/1.1.0/) e o projeto pretende seguir o [Versionamento Semântico](https://semver.org/) assim que tiver releases.

> **Este changelog foi reconstruído.** O ARMATURA **não teve nenhum release publicado**: todos os crates estão na versão `0.1.0`, não há tags (os primeiros builds são preparados como o pré-lançamento em rascunho `v0.1.0-alpha.3`, abaixo) e nenhuma nota de release foi mantida durante o desenvolvimento. As seções abaixo foram reconstruídas em outubro de 2026 a partir da seção 9 de `ROADMAP.md` (o log datado de implementação), de `FEATURES.md`, dos níveis de recursos do README e das entradas de revisão. Os nomes "0.1" a "0.7" são **níveis de recursos** que agrupam o que as fontes dizem que andava junto, não versões publicadas; a ordem dentro de um nível segue a ordem do log; as datas aparecem apenas onde uma fonte as fornece (o log tem o cabeçalho de 20 out 2026, mas contém entradas até a decisão sobre a licença de 22 out 2026). Onde o log não diz quando algo aconteceu, nenhuma data é inventada. Quando o primeiro release de verdade for feito, renomeie *Unreleased* e estes níveis para versões reais (veja [docs/DEVELOPMENT.md](DEVELOPMENT.md), checklist de release).

Versões relacionadas que **são** reais e independentes das acima: o `API_VERSION` da fachada Rust (1.0.0 a 1.4.0, abaixo), o `ABI_VERSION` da C e do WebAssembly (1) e o número `format` do arquivo de projeto ([docs/PROJECT_FORMAT.md](PROJECT_FORMAT.md)).

## Ondas de revisão e reforço (outubro de 2026)

Foram lotes de correções feitos após revisões independentes da mesma árvore. Cada correção tem um teste de regressão. Elas são listadas por onda, na ordem do log; nenhuma delas é um release.

### Onda 1 - revisão adversarial de segurança e robustez
- **S1 studio.** `tiny_http` substituído por um servidor HTTP/1.1 próprio da biblioteca padrão (`http.rs`): `Connection: close`, prazos de leitura de 10 s, 413 / 431 antecipados, limite de conexões com 503. Lista de hosts permitidos contra DNS rebinding, `Content-Type: application/json` em POST, prova de Origin / `Sec-Fetch-Site` nas rotas que modificam, CSP, `nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy: no-referrer`; `/api/save` atômico e que recusa symlinks.
- **S6 collab.** Token de pelo menos 16 caracteres por cabeçalho ou cookie `HttpOnly` a partir de um POST de login (nunca em uma URL), comparação em tempo constante, limite de taxa de tentativas falhas, ids de réplica aleatórios de 128 bits e um segredo por participante, log com modo 0600, hash do log FNV-1a substituído por SHA-256 (formato v2).
- **S2 assets.** `assets::resolve`: todo caminho de asset é canonicalizado e deve permanecer dentro do diretório do projeto (sem caminhos absolutos, `..`, escapes por symlink), a menos que se use `--allow-external-assets`; somente arquivos regulares; limites de 256 MB para áudio e 64 MB para imagem; ffmpeg e ffprobe recebem `-protocol_whitelist file` e nomes com prefixo `./`; foi corrigido um bug de pai vazio que poderia deixar uma URL chegar ao ffmpeg.
- **S3 limites de recursos.** Verificações do cabeçalho PNG antes da alocação (mais de 64 Mpixel ou um lado acima de 16384 são recusados), limite para JPEG, limites de saída raster, limite de `fuzz --samples`, ear clipping de GLB quase linear (60000 âncoras haviam levado 40 s), `check_budget` para exportações, size-report e lod, um limite para os valores de `import-lottie`.
- **S4 expressões.** Limite de profundidade do parser de 64 e limite de fonte de 4 KB.
- **R1 valores finitos.** Floats do JSON de projeto além de +-1e7 recusados no carregamento; erros `non-finite value in <place>` em vez de gravar NaN a partir de render, frames, export, render-hdr e export-oca; os solvers de contêiner e de rolagem rejeitam resultados não finitos.
- **R2 saída atômica.** `write_json` valida antes de gravar; toda saída da CLI é gravada de forma atômica (`fsutil::write_atomic`, symlinks recusados); os comandos recusam uma saída que seja o próprio projeto de entrada; hashes golden e caminhos de manifesto validados; nomes previsíveis em `/tmp` substituídos por diretórios temporários exclusivos privados 0700.
- **R3** `println!` / `eprintln!` seguros contra pipe fechado. **R4** `check`, `lint` e `studio` reportam `unknown field <path>`; chaves desconhecidas em uma transição ou condição de máquina de estados são um erro. **R5** Documentação de WASM corrigida: `catch_unwind` não faz nada sob `panic=abort`; `arm_render_rgba` recusa saídas acima de 256 MB.
- Removido: a dependência `tiny_http` (e `ascii`, `chunked_transfer`, `httpdate`).

### Onda 7 - os itens em aberto da lista de limitações
- **A. | 1.3.0 | Operações de escrita: `vcs_*` (init, commit, branch, tag, checkout, merge, cherry-pick, revert, conflicts, resolve, abort) e `ci_*` (init, run, bless); `ApiError::{DirtyTree, MergeInProgress, Conflicts}` |
| 1.4.0 | `add_rect_layer` / `add_ellipse_layer` / `add_group_layer` / `add_bone`, `bake_physics`, `ExportFormat::Apng`, `render_exr`, `vcs_branches` / `vcs_branch_delete` / `vcs_status` / `vcs_diff` / `vcs_show` / `vcs_gc` / `vcs_fsck`; a ABI C ganhou as funções básicas de edição e de exportação para memória (versão da ABI ainda 1) |

As versões são as que o log nomeia; as operações de escrita da 1.3.0 **não** são expostas pela ABI C nem pelo wasm (a CLI tem seus próprios comandos); a partir da 1.4.0 a ABI C expõe as funções básicas de edição e a exportação para memória. A lista autoritativa de cada item é `armatura-core/src/api_surface.txt` e [docs/API.md](API.md).
