# Bekannte Einschränkungen

*Was OSATURA nicht kann, nur teilweise kann oder bei dem nicht gezeigt wurde, dass es funktioniert. Zusammengetragen aus den Aussagen „NOT done“ und „limits that remain“ in `ROADMAP.md` Abschnitt 9, aus den anderen Dokumenten und aus dem, was beim Schreiben dieser Dokumentation beobachtet wurde. Dokumentation unter CC-BY-4.0. Nichts davon ist verstecktes Kleingedrucktes: Wenn dir eine Grenze wichtig ist, eröffne ein Issue.*

So liest du die Tabellen:

* **Severity** ist die Auswirkung auf einen typischen Benutzer: **High** = blockiert eine Hauptanwendung oder kann Arbeit bzw. Sicherheit gefährden; **Medium** = eine sichtbare Lücke mit einem gangbaren Umweg; **Low** = ein Randfall, eine Politur oder eine Forschungsgrenze.
* **Workaround**: was du heute tun kannst. „None“ bedeutet, dass keiner bekannt ist.
* **Roadmap**: der Eintrag in `ROADMAP.md` (R-xxx geordneter Plan, I-xx Innovationen), zu dem die Einschränkung gehört. Für eine dort als „NOT done“ aufgeführte Einschränkung ist keine Arbeit geplant; die Roadmap-ID sagt, wo sie liegen geblieben ist.
* Die IDs `L-nn` dienen dazu, aus einem Issue oder von einer anderen Seite auf eine Einschränkung zu verweisen.

Zwei Tatsachen prägen alles Folgende. Erstens wurde **OSATURA von einem Projekt in einer Umgebung gebaut, getestet und geprüft** (Linux x86-64, keine echte GPU, keine Webcam, kein anderer Browser als Headless-Chromium, kein Netzwerkzugang zum Installieren weiterer Targets); was diese Umgebung nicht konnte, ist als „not tested“ aufgeführt, nicht als „funktioniert“. Seit dem 24. Okt. 2026 liefert eine zweite Umgebung weitere Belege: GitHub Actions führt die Tests unter Linux, macOS und Windows aus und baut die Programme und das WebAssembly-Modul (die Punkte L-01, L-04, L-59, L-61, L-64 sagen genau, was das belegt). Zweitens **gibt es nur eine Entwurfs-Vorabversion**: `v0.1.0-alpha.3` ist gebaut und vorbereitet, aber nicht veröffentlicht, alle Crates stehen auf 0.1.0, und die Versionsnamen „v0.5 / v0.6 / v0.7“ sind Feature-Stufen (siehe [CHANGELOG.md](CHANGELOG.md)).
