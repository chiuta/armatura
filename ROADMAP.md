# ARMATURA — Ordered implementation roadmap (clean-room, IP-safe)

Status of this file: planning document derived from `FEATURES.md` (rounds 1–9 of public-source research, 19 Oct 2026).
Everything here is **simple → complex**, ordered so that each item only depends on items above it.
**Not legal advice.** The IP notes are an engineering risk screen; have a lawyer confirm anything marked 🟡 before shipping.

Legend — Risk: 🟢 safe (open standard, textbook maths, or our own design) · 🟡 review before shipping · 🔴 do not do.
Effort: S ≤ 1 day · M = days · L = weeks · XL = months.

---

## 0. Clean-room rules (apply to every item)

1. **Specify from public behaviour only.** Allowed inputs: published user manuals, release notes, vendor videos, open standards, academic papers, open-source code under compatible licences (read for ideas, never copy code; check the licence before even reading GPL code you might reimplement).
2. **Two-role process.** Whoever writes a feature note (`docs/specs/R-xxx.md`) cites its public source. Whoever implements reads only that note + standards/papers, not the vendor product's internals.
3. **Provenance log.** Every item gets one line in `CLEANROOM.md`: item id · public sources · date · implementer. (R-001)
4. **Never** use cracked/pirated builds, leaked docs, decompilation, or network-traffic reverse engineering of competitors. (In the EU, Directive 2009/24/EC limits decompilation to narrow interoperability cases — we do not rely on it.)
5. **Own names, own formats.** Use our vocabulary (pose driver, not "Smart Bone"; take/clip, not "replay"). Competitor names appear only descriptively in documentation (nominative use), never in UI, file extensions, crates or marketing.
6. **Open formats only for interchange** (list in §2). Proprietary binary formats are out unless the vendor publishes a licence that allows it.
7. **Patents:** prefer textbook/older algorithms, and our own designs. Avoid re-implementing any technique that is the subject of a known patent claim (see §3).
8. **Codecs:** keep encoders external (user-installed ffmpeg). Default to openly specified codecs (VP9/AV1/APNG/PNG); their patent status is not assessed (docs/PATENT_NOTES.md). Treat H.264/AAC/ProRes as optional, user-side, with a note.
9. **Fonts, brushes, sample art:** only CC0/OFL/own work.

## 2. Known patent/copyright hot-spots (screening list)

| Area | Source seen | Our stance |
|---|---|---|
| Fast 2-D mesh deformation solver for artwork (Adobe US9865073, US10078910) | patents | 🔴 don't implement as-rigid-as-possible-style solvers described there. Use Bernstein FFD, linear-blend skinning, cage coordinates, our own weights. Counsel review before any ARAP-like solver. |
| Face-tracking-driven puppeteering, lip-sync specifics | Character Animator | 🟡 generic audio→viseme and landmark→parameter mappings are fine; avoid copying behaviour names/UI; model weights must be permissively licensed |
| Interactive state machines / data binding (Rive, Lottie) | runtimes | 🟡 design our own semantics; don't copy schema or terminology; screen for patents before shipping |
| Physics constraints (Spine 4.2-style) | blog/docs | 🟢 damped springs are textbook; our solver is already independent (closed-form baked) |
| Image-trace, mesh-from-alpha | many | 🟢 marching squares / contour tracing are classic; Potrace is GPL — implement our own |
| Marching squares, metaballs, FABRIK, FFD, Delaunay, BBW, MVC | papers | 🟢 published research; cite papers; verify no commercial patent on any technique we choose before implementing |
| Photosensitivity analysis (Harding) | industry | 🔴 do not mimic proprietary tools; implement the public WCAG 2.3.1 / ITU-R BT.1702 definitions only |
| UI look-and-feel | all | 🟢 original design; no copied layouts, icons, sounds |

## 4. Innovations — ideas not found in any source consulted (rounds 1–9)

"Not found" means: I did not see these in the vendor pages, release notes, forums, repositories, reviews or papers I read. They may exist somewhere I did not look; treat novelty as unverified until a prior-art check. Each one leans on what ARMATURA already has: **evaluate(frame) is a pure function**, **every edit is a JSON-pointer op with an exact inverse**, **every edit is revalidated**, **everything is deterministic**.

| ID | Idea | Why it is new relative to the sources | How it works here | First milestone | Risk | Needs |
|---|---|---|---|---|---|---|
| **I-01** | **Animation version control with semantic merge ("ArmaGit")**: branches, history, and 3-way merge of two animators' edits at the level of channels/keys/bones (not text). | Sources show real-time co-editing (Rive), revision restore, and Perforce-style file locking; none showed branch-and-merge of animation data. | Op-log + inverses give lossless history; merge = rebase ops, conflicts only when both touch the same channel/time. | `armatura merge base.json a.json b.json` | 🟢 | R-004, R-003 |
| **I-02** | **Rig linter (static analysis of rigs)**: flags IK flip zones, angle-wrap jumps, spring instability, draw-order cycles, unreachable constraints, dead channels, huge weights, non-finite risk — with suggested fixes. | Sources have "rigging issues pane" (Adobe) and validation errors; none ran a rule-based analyser that explains and auto-fixes. | Reuse `Engine::new` validation + numeric probes; each rule is a small module with id, severity, fix op. | 10 rules + `armatura lint` | 🟢 | R-002 |

## 5. Recommended first three milestones

**M2 — Production output (Tier 2 + Tier 3 core: R-020..R-025, R-030..(R-034 effects/precomps only), R-03A).** Outcome: filters, masks, onion skin, alpha video, sprite sheets, richer Lottie, SVG in/out.

## 8. Better clean-room alternatives for every 🟡 / 🔴 item (implemented)

Principle: replace each risky item with something that is **(a) built on a public open standard or textbook maths, (b) our own design where no standard exists, and (c) at least as capable**. Status below is real code with tests (185 passing).

| Risky item (§) | Alternative implemented | Where | Why it is safer *and* better |
|---|---|---|---|
| 🔴 Fast ARAP-style mesh deformation (Adobe patents) — §2 | **Pin warp**: compactly supported RBF (Wendland 1995), `Deformer::Pin` | `pinwarp.rs` | Exact pin interpolation, C² smooth, strictly local (zero beyond radius), no mesh and no iterative solver; linear in pin offsets so it blends and keys perfectly. Pins are animatable (`PinDx/PinDy`). |
| 🟡 R-060 Cage deformer (MVC) | Same pin warp for free-form edits; Lattice (Bernstein FFD) and Spine stay for structured ones | `pinwarp.rs`, `engine.rs` | Pins are quicker to author than cages. Update: a cage deformer now exists too (`cage.rs`), built from the textbook mean-value-coordinate formula of Floater 2003 (published academic paper, own implementation), so the original claim of avoiding cage-coordinate techniques entirely NO LONGER HOLDS; its patent screening is not done (docs/PATENT_NOTES.md). Pin warp remains for quick edits. |
| 🟡 R-062 Heat-diffusion auto-weights | **Harmonic diffusion on the mesh graph** (Gauss–Seidel, partition of unity), influence limiting, smoothing, nearest-transfer, L/R mirror | `weights.rs`, `Project::auto_skin_diffuse`, CLI `skin-diffuse` | Textbook Laplace equation; no leaking across gaps; deterministic. |
| 🟡 R-112 ML assist (auto-trace) | **Marching squares + Douglas–Peucker tracing**, holes via Boolean difference | `trace.rs`, CLI `trace` | No model weights, no licences, no network; exact and reproducible. |
| 🟡 R-112 ML assist (pose suggestions) / I-13 | **(μ/μ_w, λ) evolution-strategy pose match** with joint limits, evaluated through the real engine | `posematch.rs`, CLI `pose-match` | Derivative-free, works with any rig incl. IK; result is plain keyed channels. |
| 🟡 R-041 Takes & performance recording | **RDP key reduction** of sampled input with a stated error bound | `perf.rs::simplify_samples/record` | Public algorithm; guaranteed ≤ tolerance error (`max_error`). |
| 🟡 R-082 Webcam landmarks → parameters | **Tracker-agnostic input mapping** (CSV/JSON signals → range/deadzone/curve/smoothing → channels). Any permissively licensed tracker can feed it; none is bundled; landmark stream + geometry + calibration + One-Euro in `faceparam.rs`, CLI `face-bake`/`face-calibrate`, studio webcam hook; own detector `facedet.rs` for synthetic/cartoon faces only, untested with a camera or photographs | `perf.rs::InputMap/drive`, `faceparam.rs`, CLI `drive`, `face-bake` | No model or SDK dependency; also drives from MIDI/OSC/game-pad logs. |
| 🟡 I-12 Intent retargeting | **Effector-reach retargeting**: scale effector motion by limb-reach ratio, re-point at destination IK targets | `perf.rs::retarget_effectors`, CLI `retarget` | Rig-shape independent, no bone-name copying; non-scalable channels are reported, not silently wrong. |
| 🟡 R-091 State machine + data binding | **Deterministic event-log state machine**: pure `simulate(machine, events)` and `bake` to ordinary channels | `statemachine.rs`, CLI `state-bake` | Own schema/semantics (no Rive/Lottie terms); reproducible; baked output needs no runtime. |
| 🟡 H.264/AAC encode | **APNG, WebM VP9/AV1 with alpha, sprite sheet + JSON, OCA** as defaults; H.264 only on explicit `.mp4` via the user's own ffmpeg | `open_formats.rs`, CLI `export` | Openly specified codecs, real transparency, no codec is bundled (ffmpeg is an external process); see docs/PATENT_NOTES.md. |

Then: R-111 real-time multi-user editing (`collab.rs` and `collabhub.rs` in armatura-core; `collab_srv.rs` and the studio page in armatura-cli; CLI `collab-sim <project> [--clients N] [--ops M] [--seed S] [--undo-pct P] [--replays K] [--json]`; studio options `--bind ADDR`, `--collab-token T`). Own design from textbook ideas: Lamport 1978 logical clocks, vector clocks, Shapiro et al. 2011 CRDTs (last-writer-wins register, tombstones, operation-based with causal delivery), Roh et al. 2011 RGA for sequences. The project JSON is a tree of objects (one LWW register per key), arrays (RGA sequences with tombstones) and scalars; every container and array element has a stable identity `(replica, seq, i)`, so the editor's index-path ops (`Op::Insert/Set/Remove/Batch`) are translated against the replica's current tree into identity-addressed primitives, which is what makes a stale index land on the right element. A `Set` of a whole object or array is diffed (per key; arrays by longest common subsequence; objects with a different `id`/`name`/`target`/`prop` count as different entities), so two users changing different keys of one channel both survive. Rules: scalar and key writes are last-writer-wins by `(lamport, replica, index)`; a key delete is an ordered write, not a winner; an array remove is a tombstone and REMOVE WINS over concurrent edits inside the element (the edit is applied to the hidden element, so all replicas still agree); concurrent inserts at one place are both kept, ordered by `(lamport, id)`; a primitive naming an unknown identity is dropped and counted, never a panic. Envelope `{replica, seq, lamport, deps, ops}`; causal delivery buffer (holds an envelope until its predecessors and `deps` are applied); idempotent re-delivery; snapshot and log compaction (log prefix dropped; tombstones and unreachable nodes purged only when every peer has exactly this replica's clock); per-user undo/redo (the inverse is expressed on identities against the current tree: only this user's edits, a part is skipped where someone wrote later); presence (name, colour, frame, cursor, selection) with expiry and sanitising. `Hub` is the authoritative sequencer: it merges every accepted envelope into one numbered log, keeps a proxy replica per browser user and translates that user's pointer edit in the view the user had (`base` = log position), validates the merged JSON by compiling the project (an invalid merge is refused whole, nothing changes) and publishes events.
